# Scope Reply Patterns

Principles:
- Be on the client's side: the request is usually reasonable; it just isn't free.
- Reference the agreement, not your feelings. "In the proposal we scoped…" beats "I can't keep doing extras".
- Always give options. A choice feels like control; a "no" feels like a wall.
- Price and time impact in the same message, so the client can decide without another round-trip.
- Short. No apologising for charging, no long justification.

## Patterns

**Change, quote it**
> Love this idea, a gift-wrap option should lift order value. It's outside what we scoped for this phase (the proposal covers checkout as-is), so here are the options:
> 1. Add it now: <cur> 450, and launch moves from 14 to 17 Nov.
> 2. Swap it for the wishlist page, which is about the same effort, and keep the date.
> 3. Park it for phase 2 right after launch.
> Which works best?

**Favour, once, named as such**
> Sure, I'll swap those two images today. Heads-up that content updates aren't part of the build scope, so I'm happy to do this one as a quick favour. For future ones I can bundle them into a small content package if that's easier.

**Revisions used up**
> Happy to do another round. We've used the two rounds included in the plan, so this would be an extra round at <cur> 300. If you'd prefer, send all remaining feedback in one list and I'll handle it as one round.

**Clarification**
> Quick check so we're aligned: I read "blog" in the scope as the blog template plus the first 3 posts loaded. Adding the 40 older posts would be extra (about <cur> 200). Does that match what you had in mind?

**New project**
> This sounds like a bigger piece than a tweak: a full member area is its own project. Let's get the current launch done on the 14th, and I'll send a separate proposal for the member area this week so you can see options.

**Deadline pulled in**
> I can try for the 10th instead of the 14th, but to do that I'd need to move other work, so it'd be a <cur> 400 rush fee. Or we keep the 14th as planned. Your call.

## Tone checks
- First sentence is positive or neutral.
- No "unfortunately", "as per the contract", "per my last email".
- One question at the end.
- Match the client's language.
