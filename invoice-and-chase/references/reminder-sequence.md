# Payment Reminder Sequence

Assume good faith: most late invoices are forgotten, not disputed. Each stage gets a little firmer, never rude. Always restate invoice number, amount, due date, and how to pay (or attach/link the invoice) so the client can pay in one step.

| Stage | When | Tone | Goal |
|---|---|---|---|
| 0 | 2–3 days **before** due (optional, for new clients or big amounts) | Friendly heads-up | Avoid lateness entirely |
| 1 | 1–3 days overdue | Light, assumes it slipped | Get it paid or get a date |
| 2 | ~7–10 days overdue | Direct, asks for a date | Commitment to a payment date |
| 3 | ~21 days overdue | Firm, states consequences the user has chosen | Payment or a plan |
| 4 | 30+ days overdue | Final notice | Escalation decided by the user |

## Templates

**Stage 0: heads-up**
> Hi <name>, quick heads-up that invoice INV-2026-001 (<cur> 1,650) is due on Friday. Payment details are on the invoice; shout if you need anything from me.

**Stage 1: gentle nudge**
> Hi <name>, hope the launch is going well! Just flagging that INV-2026-001 for <cur> 1,650 was due on 18 Oct. Could you check it's in the queue? I've attached it again for convenience.

**Stage 2: ask for a date**
> Hi <name>, following up on INV-2026-001 (<cur> 1,650), now 9 days overdue. Could you let me know when it's scheduled to be paid? If there's an issue with the invoice, tell me and I'll sort it out right away.

**Stage 3: firm**
> Hi <name>, INV-2026-001 (<cur> 1,650) is now three weeks overdue and I haven't heard back. I need this settled by <date> please. <If the user chose: "Until then I'm pausing further work on the project." / "As per our terms, a late fee of X applies from <date>.">

**Stage 4: final notice**
> Hi <name>, this is a final notice for INV-2026-001 (<cur> 1,650), due on 18 Oct and now 30 days overdue. Please pay by <date>. <Only the next step the user has explicitly chosen, e.g. "After that I'll pass it to a collection service.">

## Rules

- Stages 3–4 consequences (pausing work, late fees, collections, small claims) only if the user explicitly picks them; late fees only if they were in the agreed terms.
- If the client has replied with a date, don't send the next stage; remind the user to follow up the day after that date.
- If the client disputes the invoice, stop the sequence and help the user respond to the dispute instead.
- If work is still ongoing, suggest the user pause new deliverables (not hold finished work hostage) after stage 2–3.
- Match the language and channel the client normally uses.
